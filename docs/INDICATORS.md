# Indicator contract

All calculations consume one canonical, timestamp-ordered native candle series. Completed candles come from the authoritative SQLite native-period store. A forming candle may be appended in memory for the live overlay; it never replaces a completed candle or enters historical storage. A missing period starts a new contiguous run and restarts initialization.

The list and chart project the same calculation. Their visible windows cannot choose the seed. Older price additions and historical price corrections invalidate the affected generation and later checkpoints; formula or input-schema changes invalidate incompatible derived state. OI/Taker revisions do not invalidate price indicators. Unknown volume remains unknown instead of being inferred from price.

Batch initialization and incremental updates use the same formulas. Confirmed state retains the recursive EMA/Wilder accumulators and fixed rolling windows. Each forming revision projects from a copy of that bounded state, without advancing the confirmed seed. Missing periods reset it. Historical corrections and prepends resume exact rebuilding from the nearest valid earlier checkpoint. Resident seeds and navigation ranges are bounded; the canonical prefix is read in chunks rather than retained or transferred as a full history. Checkpoints also retain the contiguous BOLL-expansion summary, independently of the displayed tail.

| Indicator | Formula and initialization |
| --- | --- |
| EMA(200) | First value is the mean of the first 200 closes of a contiguous run. Subsequent values are `close × 2/201 + previousEMA × 199/201`. |
| BOLL(20,2) | Middle is the arithmetic mean of 20 closes. Population deviation is `sqrt(sum((close − mean)²)/20)`. Upper/lower are `mean ± 2 × deviation`. A negative lower band is a valid result; the chart uses a linear price axis when a nonpositive band cannot be plotted logarithmically. |
| VWAP(14) | Rolling `sum(((high + low + close)/3) × baseVolume) / sum(baseVolume)` across 14 candles. Base volume is OKX candle `volCcy`, not contract count or quote amount. Missing/negative quantity or a zero total gives no value. This is a candle typical-price approximation, not tick-level execution VWAP. |
| ROC(9) | Signed relative change of the current close from the close nine candles earlier. First valid value is the tenth candle. |
| MAROC(9) | Arithmetic mean of nine consecutive valid ROC(9) values. First valid value is candle 18. Missing ROC cannot be treated as zero. |
| RSI(6/12/24) | Seed mean positive/negative close changes over the period; continue with Wilder smoothing `(previous × (period−1) + current)/period`. Both means zero gives 50; only loss zero gives 100; only gain zero gives 0. First valid sample needs `period + 1` closes. |
| ATR%(14) | True range is `max(high − low, abs(high − previousClose), abs(low − previousClose))`; the first candle of a contiguous valid run uses `high − low`. Seed ATR with the arithmetic mean of the first 14 true ranges, then use Wilder smoothing `(previousATR × 13 + currentTR)/14`. Display `ATR / close × 100%`, first available at candle 14. A flat range gives 0%. A nonpositive close cannot normalize ATR and gives no percentage. Nonfinite high/low or a range that excludes the close resets only ATR initialization; the next valid candle starts with `high − low`. This is a volatility ratio, not a signed relative change. |
| BBW(20,2) | Reuse the canonical BOLL(20,2) bands: `(upper − lower) / middle × 100%`. First value needs 20 contiguous closes, exactly like BOLL. A flat positive-price window gives 0%; unavailable bands, a nonpositive middle, or a nonfinite result gives no value. BBW shares the ATR% panel; each curve has an independent scale fitted to its own visible minimum and maximum with 5% range padding, clamped at zero. A constant positive series is centered within a ±5% range; an all-zero series stays at zero. Missing observations do not enter the range. Vertical coordinates are hidden; legends still show the original percentage values. BBW also supplies the width used by the BOLL-expansion checkpoint; it adds no independent window or source requests. This is a volatility ratio, not a signed relative change. |
| Signed relative change | `(current − previous) / abs(previous) × 100%`. Missing, nonfinite or zero baseline gives no value, displayed as `—`. |
| Taker imbalance | `(buyContracts − sellContracts) / (buyContracts + sellContracts) × 100%`. A zero total gives no value. This is a participation ratio, not a relative change. |

OI and Taker Buy/Sell retain contract units and native candle periods. Unavailable statistics remain explicit gaps, never fabricated zeroes. Floating-point assertions use independent expected values with a stated tolerance; agreement with a second invocation of production code is not proof of mathematical correctness.

## Checkpoint correctness

A checkpoint stores the confirmed native timestamp, complete recursive state and rolling windows, formula version, source price revision, and BOLL-expansion state. The writer rejects a checkpoint calculated against an obsolete price revision. Price correction, prepend, or replacement atomically invalidates checkpoints at and after the affected timestamp; appending later prices leaves earlier checkpoints valid. Statistics changes preserve price checkpoints.

Replay starts from the nearest valid checkpoint before the required range and processes bounded chronological chunks with the same append function used for live confirmations. Without a valid checkpoint, exact initialization can require the available canonical prefix. The 200 earlier price candles requested for warmup establish an initial coverage reserve; they cannot replace the influence of earlier inputs to a previously initialized EMA, Wilder RSI, or Wilder ATR. A viewport or retention boundary never silently chooses a new seed.

OHLC publication does not wait for this replay. Indicator values remain unavailable while exact state is being rebuilt; OI/Taker readiness is independent as well. Forming updates continue to project from a copied confirmed state, and no forming revision is persisted as a confirmed observation.
